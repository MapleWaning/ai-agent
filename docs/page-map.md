# 页面说明文档（page-map.md）

## 1. 文档目的

本文档用于说明 AI Agent 聊天系统前端页面结构、页面布局、路由设计、主要交互状态和组件划分，供前端 Agent 生成 Vue 3 项目时使用。

本项目的前端重点不是传统后台管理系统，而是一个以 **Agent 聊天主界面** 为核心的应用。用户进入系统后首先看到主界面背景，但在未登录状态下，主界面不可操作，并弹出登录 / 注册小窗口。

---

## 2. 整体页面设计原则

1. 前端只与 Java 后端通信，不直接调用 Python AI 服务。
2. 登录后进入主界面，主界面由三栏组成：左侧会话列表、中间聊天框、右侧文件列表。
3. 登录页和注册页不作为独立全屏页面展示，而是以弹窗形式覆盖在主界面之上。
4. 未登录时，主界面作为背景展示，但应加模糊和遮罩效果，禁止用户操作。
5. 登录成功后关闭弹窗，取消背景模糊，用户可以正常使用主界面。
6. 在未选择会话或尚未创建会话时，聊天区域显示欢迎页，右侧文件列表为空。
7. 第一次发送消息时，如果当前没有会话，需要先自动创建会话，再发送消息。
8. 每次对话都需要显示本次路由到的 Agent 类型，例如 RAG、MCP、Workflow 等。
9. 如果本次对话路由到 Workflow 模式，需要展示工作流思考流程和最终结果。
10. 文件列表始终对应当前选中的会话；没有进入会话时，文件列表为空。

---

## 3. 页面路由设计

### 3.1 推荐路由表

| 路由路径 | 页面组件 | 是否需要登录 | 说明 |
|---|---|---|---|
| `/` | `MainView.vue` | 否 | 主界面入口。未登录时展示登录弹窗，背景模糊；已登录时展示完整主界面。 |
| `/chat` | `MainView.vue` | 是 | 聊天主界面，未选中具体会话时显示欢迎状态。 |
| `/chat/:chatId` | `MainView.vue` | 是 | 选中某个会话后的聊天主界面，加载对应历史消息和文件列表。 |

### 3.2 登录 / 注册展示方式

登录和注册不建议作为独立页面，例如 `/login`、`/register`，而是作为主界面上的弹窗状态。

推荐用状态控制：

```ts
const authModalMode = ref<'login' | 'register'>('login')
const showAuthModal = computed(() => !userStore.isLoggedIn)
```

如果项目需要保留 `/login` 或 `/register` 路由，也应当跳转回 `/` 并以弹窗形式展示，不要进入全屏独立页面。

## 4. 主界面整体布局

### 4.1 登录后的主界面布局

主界面采用上下结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航栏                                                     │
│ 左：项目名称                              右：用户标志 用户名 退出 │
├───────────────┬──────────────────────────────┬───────────────┤
│ 左侧会话列表   │ 中间聊天框                    │ 右侧文件列表   │
│               │                              │               │
│ - 新建会话     │ - 消息展示区                  │ - 当前会话文件 │
│ - 会话记录     │ - 路由类型提示                │ - 下载         │
│ - 修改标题     │ - Workflow 步骤展示           │ - 删除         │
│               │ - 输入框                      │               │
└───────────────┴──────────────────────────────┴───────────────┘
```

### 4.2 未登录时的显示效果

用户第一次进入系统时，依然显示主界面背景，但需要叠加登录 / 注册弹窗：

```text
┌──────────────────────────────────────────────────────────────┐
│ 模糊的主界面背景                                               │
│                                                              │
│              ┌────────────────────────────┐                  │
│              │        登录 / 注册弹窗       │                  │
│              │                            │                  │
│              │  用户名输入框                │                  │
│              │  密码输入框                  │                  │
│              │  登录按钮                    │                  │
│              │  切换到注册                  │                  │
│              └────────────────────────────┘                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

未登录状态要求：

1. 主界面背景使用 `filter: blur(...)` 或半透明遮罩实现模糊效果。
2. 登录 / 注册弹窗居中显示。
3. 背景区域不可点击，不允许创建会话、发送消息、下载文件等操作。
4. 登录成功后关闭弹窗，恢复主界面正常显示。
5. 注册成功后可以自动切回登录弹窗，也可以直接登录，具体以接口能力为准。

## 5. 顶部导航栏说明

### 5.1 位置

顶部导航栏位于整个页面最上方，横向占满屏幕。

### 5.2 左侧内容

左上方显示项目名称，例如：

```text
AI 恋爱咨询智能体
```

也可以使用更简洁的名称，例如：

```text
Love Agent
```

### 5.3 右侧内容

右上方显示：

1. 用户标志，例如头像图标或圆形用户图标。
2. 当前登录用户名。
3. 退出登录按钮。

示例：

```text
👤 maple    退出登录
```

### 5.4 退出登录交互

点击退出登录后：

1. 清除本地 token / session 状态。
2. 清除 Pinia 中的用户信息。
3. 清空当前会话选中状态。
4. 回到主界面未登录状态。
5. 重新显示登录弹窗。
6. 主界面背景重新变为模糊不可操作状态。

## 6. 左侧会话列表区域

### 6.1 位置

左侧区域固定显示在页面左栏。

推荐宽度：

```text
260px ~ 320px
```

### 6.2 功能

左侧会话列表需要支持：

1. 展示当前用户的所有会话记录。
2. 点击某个会话后，中间聊天框加载该会话历史消息。
3. 点击某个会话后，右侧文件列表加载该会话对应文件。
4. 支持创建新会话。
5. 支持修改会话标题。
6. 可选支持删除会话，如果后端已有接口。

### 6.3 会话项展示内容

每个会话项建议展示：

| 内容 | 说明 |
|---|---|
| 会话标题 | 用户自定义标题或默认标题。 |
| 最近更新时间 | 如果后端返回，可展示。 |
| 当前选中状态 | 当前会话需要高亮。 |
| 编辑按钮 | 用于修改会话标题。 |

### 6.4 新建会话交互

点击「新建会话」后：

1. 可以只清空当前聊天区，进入未创建会话状态。
2. 不一定立即调用创建会话接口。
3. 当用户第一次发送消息时，再创建会话。

推荐策略：

```text
点击新建会话 → currentChatId = null → 显示欢迎页 → 用户输入第一条消息 → 调用创建会话接口 → 得到 chatId → 发送消息
```

这样可以避免用户创建空会话。

### 6.5 修改会话标题交互

点击会话项上的编辑按钮后：

1. 会话标题变为输入框，或弹出修改标题小弹窗。
2. 用户输入新标题。
3. 调用修改会话标题接口。
4. 修改成功后刷新会话列表或更新本地会话标题。
5. 修改失败时显示错误提示。

## 7. 中间聊天框区域

### 7.1 位置

中间区域是主操作区，占据页面最大宽度。

推荐布局：

```text
┌──────────────────────────────┐
│ 消息展示区域                   │
│                              │
│ 用户消息                       │
│ AI 消息                        │
│ 路由类型提示                   │
│ Workflow 思考流程              │
│ 最终结果                       │
│                              │
├──────────────────────────────┤
│ 输入框 + 发送按钮               │
└──────────────────────────────┘
```

### 7.2 未选择会话时

当用户已登录但没有选择任何会话，或点击新建会话后尚未发送第一条消息时，中间区域显示欢迎状态。

示例：

```text
欢迎使用 AI 恋爱咨询智能体
请输入你的问题，开始一次新的对话。
```

此时：

1. `currentChatId` 为空。
2. 聊天历史为空。
3. 右侧文件列表为空。
4. 用户仍然可以在输入框输入问题。
5. 用户点击发送后自动创建会话。

### 7.3 已选择会话时

当用户点击左侧某个会话后：

1. 加载该会话历史消息。
2. 中间显示历史对话。
3. 设置 `currentChatId`。
4. 右侧加载该会话文件列表。
5. 用户继续发送消息时，复用当前 `chatId`。

### 7.4 发送消息流程

发送消息时按以下流程执行：

```text
用户输入消息
  ↓
判断 currentChatId 是否存在
  ↓
如果不存在：先创建会话，拿到 chatId
  ↓
将用户消息追加到聊天框
  ↓
调用聊天 / 流式聊天接口
  ↓
展示本次路由类型
  ↓
流式展示 AI 回复或 Workflow 过程
  ↓
输出完成后刷新会话列表和文件列表
```

### 7.5 输入框要求

输入框位于聊天框底部。

要求：

1. 支持多行输入。
2. Enter 发送，Shift + Enter 换行。
3. AI 回复过程中禁止重复发送。
4. 发送后清空输入框。
5. 请求失败时恢复可编辑状态。

## 8. 路由类型提示显示

每次对话都需要显示本次路由到的类型。

### 8.1 显示位置

路由类型提示建议显示在用户消息和 AI 回复之间，作为一行系统提示。

示例：

```text
已使用 RAG 知识库问答模式
```

或者：

```text
本次请求路由到：RAG 模型
```

### 8.2 RouteType 映射

| RouteType | 前端展示文案 | 说明 |
|---|---|---|
| `normal_chat` | 已使用普通对话模式 | 普通聊天回复。 |
| `report` | 已使用报告生成模式 | 生成结构化报告。 |
| `rag` | 已使用 RAG 知识库问答模式 | 使用知识库增强问答。 |
| `mcp` | 已使用地图 MCP 模式 | 使用高德地图 MCP 能力。 |
| `tool` | 已使用工具调用模式 | 使用网页搜索、网页抓取、PDF、文件等工具。 |
| `workflow` | 已使用复杂工作流模式 | 多步骤 Agent 工作流。 |

### 8.3 样式建议

路由提示应与普通聊天消息区分开：

1. 使用浅色背景。
2. 使用小图标或标签。
3. 居中或靠左显示均可。
4. 不作为用户消息或 AI 消息气泡展示。

---

## 9. Workflow 模式展示说明

当本次对话路由到 `workflow` 模式时，前端不仅展示最终结果，还需要展示工作流思考流程。

这里的“思考流程”不是模型内部隐私推理，而是后端明确返回或流式输出的可展示步骤，例如：

```text
步骤 1：分析用户需求
步骤 2：调用 RAG 检索相关知识
步骤 3：调用地图 MCP 查询地点
步骤 4：生成最终建议
```

### 9.1 显示结构

Workflow 消息建议展示为：

```text
已使用复杂工作流模式

执行流程：
1. 正在分析用户需求...
2. 正在调用工具...
3. 正在整理最终结果...

最终结果：
这里显示 AI 最终回答内容。
```

### 9.2 交互要求

1. Workflow 步骤需要按后端流式返回逐步追加展示。
2. 当前执行中的步骤可以显示 loading 状态。
3. 已完成步骤可以显示完成标记。
4. 最终结果应与步骤区分开。
5. 如果后端返回的是普通文本流，前端应按后端约定解析步骤和最终结果。
6. 如果无法结构化解析，则直接按 Markdown 渲染完整内容。

### 9.3 组件建议

建议单独封装：

```text
WorkflowTrace.vue
```

用于展示 Workflow 的执行步骤和最终结果。

## 10. 右侧文件列表区域

### 10.1 位置

右侧区域固定显示当前会话对应的文件列表。

推荐宽度：

```text
260px ~ 340px
```

### 10.2 未进入会话时

当没有选中任何会话时，右侧文件列表为空。

展示文案可以是：

```text
暂无会话文件
```

或者：

```text
选择会话后查看生成文件
```

### 10.3 已选择会话时

当用户选中某个会话后：

1. 根据 `chatId` 查询对应文件列表。
2. 展示文件名、文件大小、创建时间等信息。
3. 支持点击下载。
4. 支持点击删除。

### 10.4 文件项展示内容

每个文件项建议展示：

| 内容 | 说明 |
|---|---|
| 文件名 | 后端返回的文件名。 |
| 文件类型 | 可根据后缀展示图标。 |
| 文件大小 | 如果后端返回则展示。 |
| 创建时间 | 如果后端返回则展示。 |
| 下载按钮 | 点击后下载文件。 |
| 删除按钮 | 点击后删除文件。 |

### 10.5 文件下载交互

点击下载按钮后：

1. 调用文件下载接口。
2. 如果后端返回二进制流，前端使用 `blob` 处理。
3. 使用后端返回的文件名或接口参数文件名作为下载文件名。
4. 下载失败时显示错误提示。

### 10.6 文件删除交互

点击删除按钮后：

1. 弹出确认提示。
2. 用户确认后调用删除接口。
3. 删除成功后刷新当前会话文件列表。
4. 删除失败时显示错误提示。

## 11. 登录弹窗说明

### 11.1 弹窗位置

登录弹窗位于页面中央。

### 11.2 登录表单字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 用户名 | input | 用户登录名。 |
| 密码 | password | 用户密码。 |

### 11.3 登录按钮

点击登录后：

1. 校验用户名和密码不能为空。
2. 调用登录接口。
3. 登录成功后保存 token / session 状态。
4. 保存当前用户信息。
5. 关闭弹窗。
6. 加载会话列表。
7. 主界面解除模糊状态。

### 11.4 切换到注册

登录弹窗底部提供切换入口：

```text
没有账号？去注册
```

点击后切换为注册弹窗，不跳转全屏页面。

## 12. 注册弹窗说明

### 12.1 注册表单字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 用户名 | input | 注册用户名。 |
| 密码 | password | 注册密码。 |
| 确认密码 | password | 前端用于二次确认。若后端不需要该字段，则仅前端校验，不提交。 |

### 12.2 注册按钮

点击注册后：

1. 校验用户名不能为空。
2. 校验密码不能为空。
3. 校验两次密码一致。
4. 调用注册接口。
5. 注册成功后显示成功提示。
6. 切换回登录弹窗。

### 12.3 切换到登录

注册弹窗底部提供切换入口：

```text
已有账号？去登录
```

## 13. 页面状态说明

### 13.1 全局状态

建议使用 Pinia 管理以下状态：

```ts
interface UserState {
  token: string | null
  userId: number | null
  userName: string | null
  isLoggedIn: boolean
}
```

### 13.2 会话状态

```ts
interface ChatState {
  currentChatId: number | null
  chatList: Chat[]
  messages: ChatMessage[]
  loading: boolean
  streaming: boolean
}
```

### 13.3 文件状态

```ts
interface FileState {
  currentChatId: number | null
  files: ChatFile[]
  loading: boolean
}
```

## 15. 页面加载流程

### 15.1 用户首次进入系统

```text
进入 `/`
  ↓
检查本地是否有 token / 登录态
  ↓
如果未登录
  ↓
显示模糊主界面背景
  ↓
弹出登录窗口
```

### 15.2 登录成功后

```text
用户登录成功
  ↓
保存登录态
  ↓
关闭登录弹窗
  ↓
取消主界面模糊
  ↓
加载会话列表
  ↓
聊天区显示欢迎状态
  ↓
文件列表为空
```

### 15.3 点击会话后

```text
点击左侧会话
  ↓
设置 currentChatId
  ↓
加载该会话历史消息
  ↓
加载该会话文件列表
  ↓
中间展示历史对话
  ↓
右侧展示文件列表
```

### 15.4 新建对话并首次发送

```text
点击新建会话
  ↓
currentChatId = null
  ↓
聊天区显示欢迎状态
  ↓
文件列表为空
  ↓
用户输入消息并发送
  ↓
调用创建会话接口
  ↓
获得 chatId
  ↓
发送聊天消息
  ↓
展示路由类型和 AI 回复
  ↓
刷新会话列表和文件列表
```

## 16. 样式风格建议

### 16.1 整体风格

建议采用简洁的应用型界面：

1. 顶部导航栏固定高度。
2. 左中右三栏高度占满剩余视口。
3. 会话列表和文件列表使用卡片或列表样式。
4. 聊天消息使用气泡样式。
5. AI 消息支持 Markdown。
6. 当前会话高亮。
7. 文件列表与聊天区视觉区分明显。

## 17. 前端 Agent 生成注意事项

生成 Vue 前端时必须遵守：

1. 登录和注册以弹窗形式展示，不要做成全屏独立页面。
2. 未登录时主界面背景需要模糊，且不可操作。
3. 主界面必须是左中右三栏布局。
4. 左侧是会话列表，中间是聊天框，右侧是当前会话文件列表。
5. 没有进入会话时，右侧文件列表为空。
6. 第一次触发对话时，如果没有 `chatId`，需要先创建会话。
7. 每次对话都必须显示本次路由类型。
8. Workflow 模式必须展示执行步骤和最终结果。
9. 文件列表需要支持下载和删除。
10. 会话列表需要支持点击查看对话和修改会话标题。
11. 顶部左侧显示项目名称。
12. 顶部右侧显示用户标志、当前用户和退出登录。
13. 不要直接调用 Python 服务，所有请求都通过 Java 后端。
14. SSE 流式接口需要按接口文档单独处理，不要当作普通 Axios JSON 请求。
15. 文件下载接口如果返回二进制流，需要使用 `blob` 下载。
