# frontend-spec.md

# 前端功能说明文档

## 1. 项目概述

本项目是一个 AI Agent 聊天系统前端，面向已完成的 Java 后端进行页面开发。前端只负责用户交互、会话展示、消息输入、流式输出展示、文件管理等功能，不直接调用 Python AI 服务。

系统整体交互链路为：

```text
Vue 前端 → Java 后端 → Python AI 服务
```

其中：

- Vue 前端只与 Java 后端通信。
- Java 后端负责用户登录注册、会话管理、聊天历史、文件管理、AI 请求转发等能力。
- Python 端负责具体 AI 能力，包括普通对话、RAG、MCP、工具调用、报告生成、Workflow 工作流等。
- 前端需要根据 Java 后端返回的数据展示不同的 Agent 执行结果。

---

## 2. 前端功能范围

前端需要实现以下核心功能：

1. 登录
2. 注册
3. Agent 聊天
4. 会话列表
5. 会话创建
6. 会话标题修改
7. 历史对话查看
8. 消息发送与 AI 流式回复展示
9. 本次对话路由类型展示
10. Workflow 工作流思考流程展示
11. Workflow 最终结果展示
12. 会话文件列表查看
13. 文件下载
14. 文件删除

不需要实现以下功能：

1. 用户详情页
2. 用户资料修改
3. 管理后台
4. 权限管理页面
5. 用户列表管理

---

## 3. 页面结构

建议前端至少包含以下页面。

### 3.1 登录页

路由建议：

```text
/login
```

功能说明：

- 用户输入账号和密码。
- 点击登录按钮后调用 Java 后端登录接口。
- 登录成功后保存登录态，例如 token、session 标识或后端要求的认证信息。
- 登录成功后跳转到 Agent 聊天页面。
- 登录失败时展示错误提示。

页面元素：

- 用户名输入框
- 密码输入框
- 登录按钮
- 跳转注册页入口
- 错误提示区域

注意事项：

- 不需要展示用户详情。
- 登录态保存方式以 Java 后端接口文档为准。
- 如果后端使用 token，前端后续请求需要自动携带 token。
- 如果后端使用 session/cookie，前端请求需要支持携带 cookie。

---

### 3.2 注册页

路由建议：

```text
/register
```

功能说明：

- 用户输入注册信息。
- 点击注册按钮后调用 Java 后端注册接口。
- 注册成功后跳转登录页。
- 注册失败时展示错误提示。

页面元素：

- 用户名输入框
- 密码输入框
- 确认密码输入框
- 注册按钮
- 返回登录页入口
- 错误提示区域

注意事项：

- 注册页只负责创建用户。
- 不需要注册后进入用户详情页。
- 是否需要自动登录，以后端接口和实际设计为准。

---

路由建议：

```text
/chat/:chatId
```

页面布局建议：

```text
┌───────────────────────────────┐
│ 顶部栏：系统名称、当前用户、退出登录 │
├───────────────┬───────────────┤
│ 左侧会话列表   │ 右侧聊天区域    │
│               │               │

│               │ - 发送按钮      │
```

核心功能：

## 4. 会话列表功能

### 4.1 会话列表展示

功能说明：

- 左侧展示当前登录用户的所有会话。
- 每个会话展示标题。
- 如果有时间字段，可以展示最近修改时间或创建时间。
- 当前选中的会话需要高亮。

会话项建议展示内容：

| 字段 | 说明 |
|---|---|
| 会话标题 | 用户自定义标题或默认标题 |
| 最近更新时间 | 可选 |
| 当前选中状态 | 高亮显示 |

---

### 4.2 新建会话

功能说明：

- 用户可以点击“新建会话”按钮。
- 新建会话后，可以立即进入空白对话状态。
- 也可以不立即调用后端创建接口，而是在第一次发送消息时再创建会话。

本项目要求：

- 如果当前是第一次触发对话，且还没有有效 `chatId`，则前端需要先创建会话，再发送消息。
- 创建成功后，前端保存后端返回的 `chatId`。
- 后续消息都使用该 `chatId` 继续对话。

推荐流程：

```text
用户点击新建会话
→ 前端进入空白聊天状态
→ 用户输入第一条消息并点击发送
→ 判断当前是否存在 chatId
→ 如果不存在，则先调用创建会话接口
→ 获取 chatId
→ 再调用聊天接口发送消息
→ 会话列表刷新
```

---

### 4.3 查看历史对话

功能说明：

- 用户点击左侧某个会话后，右侧聊天区域展示该会话历史消息。
- 历史消息应按时间正序展示。
- 用户可以继续在该会话中发送新消息。

注意事项：

- 切换会话时需要清空当前输入状态和临时流式回复状态。
- 如果当前正在接收 AI 流式回复，切换会话前应进行提示或禁止切换。

---

### 4.4 修改会话标题

功能说明：

- 用户可以修改会话标题。
- 修改方式可以是点击编辑按钮、双击标题、弹窗输入等。
- 修改成功后刷新会话列表或更新当前会话项。

交互建议：

```text
点击会话标题旁边的编辑按钮
→ 弹出输入框
→ 用户输入新标题
→ 点击确认
→ 调用修改标题接口
→ 成功后更新会话列表
```

校验建议：

- 标题不能为空。
- 标题长度应有限制，例如 1～50 个字符。
- 请求失败时恢复原标题并提示错误。

## 5. Agent 聊天功能

### 5.1 消息展示

聊天区域需要展示用户消息和 AI 消息。

消息类型建议：

| 类型 | 说明 |
|---|---|
| user | 用户发送的消息 |
| assistant | AI 回复消息 |
| system | 系统提示，例如路由类型提示、错误提示 |
| workflow_step | Workflow 工作流步骤 |
| file | 文件生成提示，可选 |

消息展示要求：

- 用户消息靠右展示。
- AI 消息靠左展示。
- AI 消息支持 Markdown 渲染。
- AI 回复过程中需要实时追加内容。
- 正在生成时显示 loading 或“正在思考中”。

---

### 5.2 第一次对话自动创建会话

本项目要求：

- 用户进入空白聊天页面时，可以不立即创建会话。
- 当用户第一次发送消息时，如果当前没有 `chatId`，前端应先调用创建会话接口。
- 创建会话成功后，再携带 `chatId` 调用聊天接口。
- 如果创建会话失败，则不发送消息，并提示用户。

流程：

```text
用户发送消息
→ 判断当前是否存在 chatId
→ 不存在 chatId
    → 调用创建会话接口
    → 保存 chatId
    → 刷新会话列表
    → 调用聊天接口
→ 存在 chatId
    → 直接调用聊天接口
```

---

### 5.3 消息发送

功能说明：

- 用户在输入框中输入消息。
- 点击发送按钮或按 Enter 发送。
- 发送后立即在消息列表中展示用户消息。
- 输入框清空。
- 在 AI 回复完成前，发送按钮进入 loading 或禁用状态，避免重复发送。

发送失败处理：

- 如果请求失败，需要展示错误提示。
- 可以允许用户重新发送。
- 不应丢失用户输入内容，或应在消息列表中标记发送失败。

---

### 5.4 AI 流式回复展示

功能说明：

- 聊天接口如果使用 SSE 或流式响应，前端需要实时展示 AI 回复。
- 每收到一段内容，就追加到当前 AI 消息中。
- 流结束后，标记 AI 回复完成。
- 流结束后可以刷新当前会话历史和文件列表。

注意事项：

- 如果后端流式接口是 POST 请求，不建议使用原生 EventSource。
- POST 流式接口建议使用 `fetch + ReadableStream` 处理。
- 流式接口的数据格式、结束标识、错误格式以 Java 后端接口文档为准。
- 前端不要把流式接口当作普通 Axios JSON 请求处理。

---

## 6. 路由类型展示功能

每次用户发送消息后，后端会对本次请求进行路由，决定调用哪种 AI 能力。前端需要将本次对话路由到的类型展示出来。

### 6.1 路由类型

路由类型包括：

| RouteType | 前端展示文案 | 说明 |
|---|---|---|
| normal_chat | 普通对话模式 | 普通恋爱咨询对话 |
| report | 报告生成模式 | 生成结构化报告 |
| rag | RAG 知识库模式 | 使用知识库增强问答 |
| mcp | 地图服务模式 | 调用高德地图 MCP 能力 |
| tool | 工具调用模式 | 调用文件、网页、图片、PDF 等工具 |
| workflow | 工作流模式 | 多步骤复杂 Agent 工作流 |

### 6.2 展示要求

前端需要在每次对话中展示一行模式提示，例如：

```text
本次对话使用 RAG 知识库模式
```

不同类型展示示例：

```text
本次对话使用普通对话模式
本次对话使用报告生成模式
本次对话使用RAG知识库模式
本次对话使用地图服务模式
本次对话使用工具调用模式
本次对话使用工作流模式
```

展示位置建议：

- 用户消息下方
- AI 回复上方
- 或作为一条 system 消息插入消息列表中

视觉建议：

- 使用标签、提示条或浅色信息块展示。
- 不要打断 AI 回复内容。
- 每一轮对话都应该有对应的路由类型提示。

---

## 7. Workflow 工作流展示功能

当本次对话路由类型为 `workflow` 时，前端除了展示最终回复，还需要展示工作流思考流程。

### 7.1 工作流展示内容

Workflow 模式下建议展示两类内容：

1. 思考流程 / 执行步骤
2. 最终结果

示例：

```text
本次对话使用工作流模式

执行流程：
1. 分析用户需求
2. 调用网页搜索工具查询资料
3. 调用地图 MCP 查询地点
4. 汇总结果
5. 生成最终回复

最终结果：
……
```

### 7.2 展示方式

推荐使用可折叠面板展示工作流过程：

```text
[工作流执行过程 ▼]
- 第一步：分析用户需求
- 第二步：调用 RAG 查询知识库
- 第三步：调用工具生成文件
- 第四步：汇总并输出结果

[最终结果]
AI 的最终回复内容
```

也可以使用时间线组件展示：

```text
步骤 1：分析用户目标
步骤 2：调用工具
步骤 3：处理工具结果
步骤 4：生成最终回答
```

### 7.3 流式展示要求

如果后端会流式返回 Workflow 步骤，则前端需要：

- 实时追加步骤。
- 每个步骤单独展示。
- 步骤完成后更新状态。
- 最终结果和中间步骤要有明显区分。

如果后端只在最终响应中返回 Workflow 步骤，则前端需要：

- 解析后端返回的步骤列表。
- 将步骤展示在 Workflow 面板中。
- 将最终结果展示在普通 AI 回复区域。

### 7.4 状态展示

每个 Workflow 步骤可以有以下状态：

| 状态 | 说明 |
|---|---|
| pending | 等待执行 |
| running | 正在执行 |
| success | 执行成功 |
| error | 执行失败 |

如果后端没有返回状态，前端可以只展示步骤文本。

## 8. 文件查看列表功能

文件查看列表用于展示当前会话生成的文件。

### 8.1 文件列表展示

功能说明：

- 用户可以查看当前会话下生成的文件。
- 文件列表和当前 `chatId` 绑定。
- 切换会话后，文件列表也需要随之刷新。
- AI 回复结束后，如果本次任务可能生成文件，应刷新文件列表。

展示字段建议：

| 字段 | 说明 |
|---|---|
| 文件名 | 文件名称 |
| 文件类型 | 可选 |
| 文件大小 | 可选 |
| 创建时间 | 可选 |
| 操作 | 下载、删除 |

注意事项：

- 字段名称以 Java 后端接口文档为准。
- 如果后端只返回文件名，则前端只展示文件名和操作按钮。
- 文件真实存储路径不应暴露给用户。

---

### 8.2 文件下载

功能说明：

- 用户点击下载按钮后，前端调用文件下载接口。
- 下载接口如果返回二进制流，前端需要使用 `blob` 处理。
- 下载文件名应尽量使用后端返回的文件名。
- 下载失败时提示错误。

交互流程：

```text
点击下载
→ 调用文件下载接口
→ 获取 blob 数据
→ 创建临时下载链接
→ 触发浏览器下载
→ 释放临时链接
```

---

### 8.3 文件删除

功能说明：

- 用户可以删除当前会话下的某个文件。
- 删除前需要二次确认。
- 删除成功后刷新文件列表。
- 删除失败时提示错误。

交互流程：

```text
点击删除
→ 弹出确认框
→ 用户确认
→ 调用删除文件接口
→ 删除成功
→ 刷新文件列表
```

注意事项：

- 删除操作应只删除当前用户当前会话下有权限访问的文件。
- 权限校验由后端完成，前端负责传递必要参数。
- 删除失败时需要展示后端返回的错误信息。

## 9. 前端状态管理

建议使用 Pinia 管理以下状态。

### 9.1 用户状态

保存内容：

- 登录状态
- token 或 session 信息
- 当前用户名
- 当前用户角色，如果后端返回

不需要保存：

- 用户详情信息
- 用户资料扩展字段

---

### 9.2 会话状态

保存内容：

- 会话列表
- 当前选中的 `chatId`
- 当前会话标题
- 当前会话历史消息
- 当前是否正在生成回复
- 当前路由类型
- 当前文件列表

---

### 9.3 聊天临时状态

保存内容：

- 当前输入框内容
- 当前正在流式输出的 AI 消息
- 当前 Workflow 步骤
- 当前请求是否正在进行
- 当前错误信息

## 12. 错误处理要求

前端需要处理以下错误场景：

| 场景 | 处理方式 |
|---|---|
| 登录失败 | 展示错误信息 |
| 注册失败 | 展示错误信息 |
| 会话创建失败 | 阻止发送消息并提示 |
| 聊天请求失败 | 展示错误提示，允许重试 |
| SSE 中断 | 标记回复异常结束 |
| 文件下载失败 | 展示错误提示 |
| 文件删除失败 | 展示错误提示 |
| 未登录或登录过期 | 清除登录态并跳转登录页 |
| 修改标题失败 | 恢复原标题并提示 |

---

## 13. UI 风格建议

整体风格建议：

- 简洁、清晰，偏应用型后台风格。
- 左侧会话列表类似 ChatGPT。
- 右侧为主聊天窗口。
- 文件列表可以放在右侧抽屉、底部面板或聊天区侧边栏。
- Workflow 步骤建议使用折叠面板或时间线。
- 路由类型提示建议使用标签或浅色提示条。

颜色建议：

- 普通对话：默认色
- RAG：蓝色或信息色
- 报告生成：紫色或强调色
- MCP：绿色或地图相关色
- 工具调用：橙色
- Workflow：深色或高亮色

具体颜色可由前端 UI 框架统一管理。

---

## 14. 非功能性要求

1. 前端只调用 Java 后端接口，不直接调用 Python。
2. 接口路径、请求字段、响应字段以 `api-contract.md` 为准。
3. 所有 API 请求统一封装。
4. SSE 流式接口需要单独封装。
5. 文件下载不能按普通 JSON 请求处理。
6. 页面刷新后应尽量保持登录态。
7. 切换会话时应正确清理当前流式状态。
8. AI 回复生成过程中应避免重复发送。
9. 删除文件、修改标题等操作需要有成功和失败反馈。
10. 代码结构应清晰，便于后续扩展 RAG、MCP、工具调用、Workflow 的展示细节。

## 15. 前端生成边界

本说明文档只描述前端功能需求，不定义最终接口字段。

前端 Agent 生成代码时需要同时参考：

```text
docs/frontend-spec.md
docs/api-contract.md
```

其中：

- `frontend-spec.md` 负责说明前端需要实现什么功能。
- `api-contract.md` 负责说明前端如何调用后端接口。
- 如果两者出现冲突，以 `api-contract.md` 中的接口定义为准。
